# Booking conversion measurement

GA4 property: existing G-1K2MBG959X. The primary new key event is `booking_completed`, with `booking_id`, `venue`, `booking_type`, and `player_count`. It is not payment revenue. Existing purchase/qualify_lead events remain unchanged for historical continuity; do not equate the legacy purchase event with a collected payment.

OpenAI Ads source: VRena Website & Booking, Pixel Y2uNue1R9VNaKHAjR1K9Ev. Conversion: Booking completed, standard base event `appointment_scheduled`. Pixel-only initial implementation: no new secrets or CAPI infrastructure. `page_viewed` is measured on consented public page navigation. One stable booking reference is used as `event_id`; same-tab duplicate booking reports are suppressed. Raw contact data is not supplied by this implementation. The provider's source settings and automatic advanced matching are separate from this code; review the conversion terms and existing marketing consent before release.

Only the server-confirmed ticket-booking success path emits the booking goal. RPC failures, unconfirmed responses, missing references and confirmation UI redisplays do not emit it. Individual, birthday and corporate bookings use the existing ticket flow across both venues. Member-created social sessions, waitlist actions, SIM racing and registrations are not counted by this ticket-booking goal; no separate success instrumentation was added to those flows.

GA4 follows analytics consent; the OpenAI SDK follows marketing (`all`) consent. Public staff/HR/admin/auth routes remain excluded. Tracking failures are isolated from booking completion. Full-consent attribution is forwarded from the marketing website to booking links using only oppref and UTM parameters, with a 30-minute per-tab attribution lifetime. No keys or tokens are logged. CSP permits only the documented OpenAI SDK/config and event hosts on public pages.

Skipped events: payment/order_created (payment not the requested success boundary), items_added (no cart), registration/subscription/trial/app events (outside this flow), lead_created (confirmed booking tracked directly), contents_viewed and checkout_started (deferred to avoid expanding the initial goal). Existing GA4 begin_checkout is retained. CAPI and user-data enrichment are omitted for this scoped browser-measurement setup; no new customer contact fields are transmitted by our code.

Validation: type checking, changed-file lint, and scripts/test-booking-measurement.mjs. Live validation must distinguish SDK loading and accepted test events from attributed ad conversions, which require an eligible real ad click. No test should create a paid customer booking without a controlled test-data plan. Browser blockers and visitors declining consent reduce measurable coverage.
